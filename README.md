# Credit MVP

MVP-система обработки кредитных заявок с пользовательским интерфейсом, REST API, ролевой моделью доступа и встроенными механизмами безопасности.

## Функциональность

- Регистрация, вход, обновление токенов и выход.
- Профиль пользователя.
- Оформление кредитной заявки клиентом.
- Просмотр заявок клиента.
- Обработка заявки менеджером (approve/reject).
- Расчёт риск-скоринга заявки.
- Экспорт отчёта в CSV и контрольная сумма записи.
- Загрузка/скачивание документов по заявке.
- Админ-методы для операционных проверок.

## Роли и доступ

- `client`:
  - `GET /profile/`, `PATCH /profile/`
  - `POST /loans/`, `GET /loans/my`, `GET /loans/{id}` (только свои заявки)
  - `POST /loans/{id}/documents/`, `GET /loans/{id}/documents/{filename}` (только свои заявки)
- `manager`:
  - все manager/admin эндпоинты
  - решения по заявкам и отчёты
- Контроль доступа реализован через JWT + middleware авторизации и проверки ролей.

## Технологии

- Go 1.25
- Chi Router
- GORM
- SQLite/PostgreSQL
- JWT (`github.com/golang-jwt/jwt/v5`)
- bcrypt (`golang.org/x/crypto/bcrypt`)
- Простой React UI (статические файлы в `web/`)

## Запуск

1. Скопировать переменные окружения:
   - `copy .env.example .env`
2. Заполнить минимум:
   - `JWT_SECRET`
   - `SEED_MANAGER_PASSWORD`
3. Запустить:
   - `go run ./cmd/api`
4. Открыть UI:
   - `http://localhost:8080/ui`

## Запуск в Docker / Docker Compose

1. Подготовить `.env`:
   - `copy .env.example .env`
   - заполнить `JWT_SECRET` и `SEED_MANAGER_PASSWORD`
2. Собрать и запустить:
   - `docker compose up -d --build`
3. Проверить:
   - API health: `http://localhost:8080/health`
   - UI: `http://localhost:8080/ui`
4. Остановить:
   - `docker compose down`

Данные и загруженные документы сохраняются в docker volumes:

- `credit_data` -> SQLite файл БД
- `credit_uploads` -> загруженные документы

## Конфигурация безопасности и данных

- Секреты и подключения берутся только из переменных окружения (`.env` не коммитится).
- Хранение паролей: bcrypt-хеш.
- Access token: JWT HS256; refresh token хранится в БД только в виде SHA-256 хеша.
- Ограничение тела запроса: `MAX_REQUEST_BODY_BYTES`.
- Ограничение brute force логина: `MAX_LOGIN_ATTEMPTS`, `LOGIN_BLOCK_DURATION`.
- Security headers + CSP:
  - для `APP_ENV=prod` включается строгий CSP;
  - для dev-режима разрешены inline/eval-скрипты для удобства отладки, при этом источники скриптов остаются только локальными (`'self'`).
- Стартовые данные:
  - при первом запуске автоматически создаются ~250 разнообразных заявок и набор клиентов;
  - в `APP_ENV=test` автосидирование отключено.
